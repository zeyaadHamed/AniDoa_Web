# AniDoa — منصة دونغهوا بترجمة عربية

AniDoa مشروع لمشاهدة قوائم تشغيل الدونغهوا (الأنمي الصيني) من خلال **مشغل YouTube الرسمي المضمّن**، مع ترجمة عربية تُنشأ بالذكاء الاصطناعي وتُحفظ للحلقات التي تمت ترجمتها.

> **مهم:** الموقع لا يستضيف ملفات الفيديو ولا ينزّلها من YouTube. التشغيل يتم من خلال مشغل YouTube، ويجب الالتزام بحقوق النشر وشروط YouTube والقوانين المحلية.

## المميزات الموجودة

- مكتبة مسلسلات تُضاف من رابط قائمة تشغيل YouTube بواسطة المدير.
- استيراد الحلقات بالترتيب وتخزين بيانات القوائم في Cloudflare KV.
- مشغل YouTube مضمّن مع طبقة ترجمة عربية مستقلة.
- ترجمة Gemini على دفعات، مع سياق متداخل وقاموس لمصطلحات الدونغهوا.
- تخزين الترجمة في KV لإعادة استخدامها بدل طلب ترجمة جديدة كل مرة.
- جلب الترجمة الإنجليزية عبر Innertube ثم Piped وInvidious ثم Supadata (اختياري).
- رفع ملف SRT أو VTT يدويًا بواسطة المدير عند فشل العثور على ترجمة.
- إعدادات للخط واللون وشفافية الخلفية ومزامنة التوقيت.
- متابعة آخر حلقة وتشغيل الحلقة التالية تلقائيًا.
- التحقق من أن الحلقة تنتمي إلى قائمة موجودة في مكتبة AniDoa قبل محاولة ترجمتها.
- حماية الترجمة اليدوية بكلمة سر المدير، وحد تقريبي لطلبات الترجمة لتقليل إساءة الاستخدام.
- ترويسات أمان أساسية واستجابات أخطاء عربية واضحة.

## التقنية

- Cloudflare Workers لتشغيل السيرفر.
- Cloudflare KV لتخزين فهرس المسلسلات والحلقات والترجمات.
- YouTube Data API v3 لجلب بيانات قوائم التشغيل.
- Google Gemini API للترجمة. المحرك مضبوط حاليًا على `gemini-3.5-flash-lite`.
- Wrangler 4.36.0 أو أحدث لإعداد Rate Limiting binding.

## تشغيل الموقع على الإنترنت — من المتصفح فقط

ليس مطلوبًا تثبيت Node.js أو تنزيل المشروع على جهازك عند استخدام Cloudflare Workers Builds. اتبع الخطوات بالترتيب.

### 1. جهّز مفاتيح الخدمات

**أولًا: YouTube Data API**

1. افتح [Google Cloud Console](https://console.cloud.google.com/).
2. أنشئ مشروعًا جديدًا أو اختر مشروعًا موجودًا.
3. افتح **APIs & Services → Library**.
4. ابحث عن **YouTube Data API v3** واضغط **Enable**.
5. افتح **APIs & Services → Credentials → Create Credentials → API key**.
6. انسخ المفتاح واحتفظ به. لا تنشره في GitHub ولا ترسله في محادثة عامة.

**ثانيًا: Gemini API**

1. افتح [Google AI Studio – API Keys](https://aistudio.google.com/apikey).
2. أنشئ API key وانسخه.
3. سيستخدم المشروع النموذج `gemini-3.5-flash-lite`. راجع [صفحة الأسعار والحصص الرسمية](https://ai.google.dev/gemini-api/docs/pricing) قبل الاستخدام العام؛ لا تفترض أن الاستهلاك غير محدود أو مجاني دائمًا.

**ثالثًا: كلمة سر المدير**

اختر كلمة سر طويلة وعشوائية لا تستخدمها في أي موقع آخر. ستدخلها داخل نموذج إضافة مسلسل، وكذلك عند رفع ترجمة يدوية. لا تضعها في ملفات المشروع.

### 2. أنشئ قاعدة التخزين KV

1. افتح [Cloudflare Dashboard](https://dash.cloudflare.com/).
2. اختر حسابك.
3. افتح **Workers & Pages → KV**.
4. اضغط **Create namespace**، واكتب الاسم بالضبط: `ANIDOA_KV`.
5. أنشئ المساحة وانسخ **Namespace ID** الظاهر لها.

### 3. ضع معرّف KV في ملف المشروع

1. افتح [ملف wrangler.toml على GitHub](https://github.com/zeyaadHamed/AniDoa_Web/blob/main/wrangler.toml).
2. بعد دمج تحديثات المشروع، اضغط زر القلم **Edit**.
3. ابحث عن هذين السطرين:

   ```toml
   id = "REPLACE_WITH_KV_ID"
   preview_id = "REPLACE_WITH_KV_PREVIEW_ID"
   ```

4. استبدل النص داخل علامات الاقتباس بمعرّف KV الحقيقي الذي نسخته في الخطوة السابقة. يمكنك استخدام نفس المعرّف في السطرين.
5. اضغط **Commit changes** لحفظ التعديل.

**ملاحظة:** لا تترك كلمات `REPLACE_WITH_...` كما هي؛ النشر لن يكتمل بهذا الإعداد. لا تنشئ مساحة KV ثانية إذا كنت قد أنشأت واحدة وبدأت تخزن فيها بياناتك؛ استخدم نفس المساحة لتجنب فقد البيانات.

### 4. اربط GitHub بـ Cloudflare للنشر التلقائي

بعد دمج تحديثات المشروع في فرع `main`:

1. افتح Cloudflare Dashboard ثم **Workers & Pages**.
2. اضغط **Create application**، ثم اختر ربط مستودع من **GitHub**.
3. وافق على طلب الربط، واختر المستودع `zeyaadHamed/AniDoa_Web`.
4. اختر فرع `main`.
5. اسم الـ Worker يجب أن يكون بالضبط `anidoa` لأنه الاسم الموجود في `wrangler.toml`.
6. اجعل **Root directory** هو المجلد الرئيسي للمستودع.
7. اترك **Build command** فارغًا؛ لا توجد خطوة بناء لواجهة منفصلة.
8. استخدم **Deploy command** التالي:

   ```bash
   npx wrangler deploy
   ```

9. اضغط **Save and Deploy**.

عند كل تحديث جديد على الفرع المتصل، يستطيع Cloudflare بناء المشروع ونشره تلقائيًا. راجع إعدادات **Workers & Pages → Worker → Settings → Builds** للتأكد من المستودع والفرع وأوامر البناء والنشر.

### 5. أضف الأسرار إلى Worker

من صفحة Worker باسم `anidoa`:

1. افتح **Settings → Variables and Secrets**.
2. اضغط **Add**.
3. اختر النوع **Secret** وليس Text/Plaintext.
4. أضف المتغيرات التالية، كل واحد على حدة:

| الاسم | مطلوب؟ | القيمة |
|---|---|---|
| `YOUTUBE_API_KEY` | نعم | مفتاح YouTube Data API v3 |
| `GEMINI_API_KEY` | نعم | مفتاح Gemini API |
| `ADMIN_SECRET` | نعم | كلمة سر المدير التي اخترتها |
| `SUPADATA_API_KEY` | اختياري | مفتاح Supadata إذا أردت تفعيل هذا المصدر الاحتياطي |

5. بعد إضافة المتغيرات اضغط **Deploy** أو **Save and Deploy** حسب الزر الظاهر.

لا تضع أيًا من هذه القيم في `wrangler.toml` أو `README.md` أو رسائل GitHub.

### 6. إعداد حد طلبات الترجمة

المشروع يحتوي في `wrangler.toml` على Rate Limiting binding باسم `ANIDOA_TRANSLATE_LIMITER` مضبوط افتراضيًا على 5 طلبات في 60 ثانية لكل مفتاح عميل/مسار. يتم نشر هذا الإعداد مع المشروع من خلال Wrangler؛ لا تضف Binding آخر بالاسم نفسه يدويًا.

هذا الحد **تقريبي** وليس نظام محاسبة أو حماية مطلقة؛ قد تتجاوز بعض الطلبات الحد مؤقتًا أثناء تحديث العدادات بين مواقع Cloudflare. قيمة `namespace_id` يجب أن تكون رقمًا موجبًا فريدًا داخل حساب Cloudflare. إذا ظهر خطأ بأن الرقم مستخدم، غيّره في `wrangler.toml` إلى رقم آخر غير مستخدم ثم أعد النشر.

### 7. اختبر الموقع

بعد نجاح النشر، سيعطيك Cloudflare رابطًا ينتهي عادةً بـ `workers.dev`.

1. افتح `https://YOUR-WORKER.workers.dev/api/health`. يجب أن يظهر رد JSON فيه `"ok": true`. هذا يؤكد أن الـ Worker يرد، لكنه لا يثبت وحده أن كل المفاتيح والخدمات الخارجية تعمل.
2. افتح الرابط الأساسي وتأكد أن صفحة AniDoa تظهر.
3. من نموذج **إضافة مسلسل جديد** الصق رابط قائمة تشغيل YouTube وأدخل كلمة سر المدير.
4. افتح المسلسل ثم اختَر حلقة.
5. إذا لم يجد النظام ترجمة إنجليزية، ارفع ملف SRT/VTT أو الصق النص، ثم أدخل كلمة سر المدير في حقل الترجمة اليدوية واضغط **ترجم الآن**.

### 8. ربط دومين خاص (اختياري)

يمكنك أولًا استخدام رابط `workers.dev` المجاني المتاح للمشروع. إذا كان لديك دومين، أضفه إلى حساب Cloudflare، ثم افتح صفحة Worker `anidoa` وانتقل إلى **Settings → Domains & Routes → Add → Custom Domain** واتبع التعليمات. قد تحتاج إعدادات DNS أو تحقق ملكية الدومين حسب حالته.

## واجهات API

| المسار | الوظيفة |
|---|---|
| `GET /api/health` | فحص استجابة الـ Worker |
| `GET /api/series` | قائمة المسلسلات |
| `POST /api/series` | إضافة قائمة تشغيل، محمية بـ `ADMIN_SECRET` |
| `DELETE /api/series?playlistId=...` | حذف مسلسل، محمي بـ `x-admin-secret` |
| `GET /api/subtitles?playlistId=...&videoId=...` | جلب الترجمة المحفوظة أو طلب ترجمة جديدة |
| `POST /api/translate-manual` | ترجمة SRT/VTT يدويًا، محمية بـ `x-admin-secret` |

## استكشاف الأخطاء

| المشكلة | ما الذي تراجعه؟ |
|---|---|
| فشل النشر أو رسالة KV ID | تأكد من استبدال القيمتين التجريبيتين في `wrangler.toml` بمعرّف KV الحقيقي |
| `ANIDOA_KV` غير متاح | تأكد من وجود مساحة KV وربطها بالاسم المطابق `ANIDOA_KV` |
| YouTube API يرجع 403 | تحقق من تفعيل YouTube Data API v3 والمفتاح والحصة اليومية وقيود المفتاح |
| Gemini يرجع 400 أو 404 | راجع صحة المفتاح وإتاحة النموذج في مشروع Google AI Studio |
| Gemini يرجع 429 | انتظر قليلًا وراجع حصة Gemini وحدود الاستخدام |
| ظهور `RATE_LIMITED` أو 429 | انتظر دقيقة ثم أعد المحاولة؛ لا تكرر الضغط بسرعة |
| الحلقة لا تملك ترجمة تلقائية | جرّب ملف SRT/VTT يدويًا؛ ويجب إدخال كلمة سر المدير |
| الحلقة غير موجودة في المكتبة | أضف قائمة التشغيل من نموذج المدير أولًا، ثم افتح الحلقة من المكتبة |

## ملاحظات مهمة قبل فتح الموقع للجمهور

- حد الترجمة يقلل إساءة الاستخدام لكنه لا يضمن منع كل تجاوز أو كل تكلفة.
- أي ترجمة آلية قد تحتوي أخطاء لغوية أو اختلافات في الأسماء والمصطلحات؛ راجعها قبل نشرها باعتبارها ترجمة رسمية.
- تابع استهلاك Google Gemini وYouTube API من لوحات التحكم، واضبط حدود الميزانية والتنبيهات المتاحة في حساباتك.
- لا ترفع ملفات لا تملك حق استخدامها، ولا تستضف أو توزّع نسخًا من فيديوهات الغير. استخدم مشغل YouTube الرسمي واحترم حقوق أصحاب المحتوى وشروط المنصات.
- لا تضع مفاتيح API أو كلمة سر المدير في المستودع العام أو في لقطات شاشة.
